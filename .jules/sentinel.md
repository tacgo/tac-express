## 2025-02-18 - XSS in Notes Panel via dangerouslySetInnerHTML
**Vulnerability:** The `notes-panel.tsx` component was rendering user-provided `note.bodyHtml` directly using React's `dangerouslySetInnerHTML` without server-side or output-time sanitization, relying solely on client-side rich-text editor sanitization during input.
**Learning:** We cannot rely solely on the input sanitization of rich-text editors for defense against XSS. While the editor may sanitize content as it's entered, tampered API requests or database manipulation could inject malicious HTML. Furthermore, we must use `isomorphic-dompurify` rather than standard `dompurify` in React to ensure consistent output and prevent hydration mismatches between SSR and CSR.
**Prevention:** Always sanitize any dynamic or user-submitted HTML directly at the presentation layer before using `dangerouslySetInnerHTML`. Specifically, in React Server Components or SSR setups, utilize `isomorphic-dompurify` to prevent server-client hydration disparities.
