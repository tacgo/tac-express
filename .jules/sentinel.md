## 2025-02-15 - Insecure Webhook Secret Generation
**Vulnerability:** The application used `Math.random()` as a fallback to generate webhook secrets when the Web Crypto API was unavailable. `Math.random()` is not a cryptographically secure pseudo-random number generator (CSPRNG) and produces highly predictable values, allowing an attacker to potentially guess secrets and forge webhook payloads.
**Learning:** In environments like older Node.js versions or specific edge runtimes, `globalThis.crypto` might not be defined. Relying on an insecure fallback like `Math.random()` silently degrades security. The "Fail Securely" principle dictates that if a required security invariant (like a CSPRNG) cannot be met, the operation must fail rather than proceed insecurely.
**Prevention:** Always verify the availability of a CSPRNG (e.g., `crypto.getRandomValues` or `node:crypto`). If neither is available, explicitly throw an error (e.g., `throw new Error("No secure random number generator available.")`) rather than providing an insecure fallback.
