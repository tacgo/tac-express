## 2024-05-14 - React.useMemo destructuring default empty array anti-pattern
**Learning:** Found an anti-pattern in how `useQuery` results were mapped and memoized using destructuring default values (e.g., `const { data = [] } = useQuery()`). In loading states, `data` is `undefined`, so this sets `data` to a *new* empty array `[]` on every render. If this `data` is then used as a dependency in a `React.useMemo` (e.g. `const rows = React.useMemo(() => data.map(toRow), [data])`), the memo block breaks because `data` keeps getting a new reference on every render, triggering unnecessary computations and re-renders for downstream table components until the query successfully completes.
**Action:** Always avoid setting fallback array references during destructuring when using `React.useMemo`. Instead, destructure the raw value `const { data } = useQuery()` and apply the fallback inline within the memo block itself: `const rows = React.useMemo(() => (data ?? []).map(toRow), [data])`.
