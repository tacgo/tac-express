# @tac Private Registry

TAC Express's private shadcn registry. Every entry has passed the Fourteen Laws gate (zero-radius, semantic tokens, paper-mono fonts, brutalist offset shadows). Run `npx shadcn@4.7.0 add @tac/<name>` to install a TAC-compliant primitive in one command — no post-processing required.

## Files

| File | Role |
|---|---|
| `registry.json` | Registry index — lists every available item with name/type/title/description/dependencies. Single source of truth, hand-edited. |
| `<name>.json` (e.g. `button.json`) | Per-item file with **inlined source content** — what `shadcn add` actually fetches. Generated by `scripts/codemods/build-tac-registry.mjs`. **Do not edit by hand** — re-run the codemod after changing the source. |

## Local-dev usage

The package's `components.json` lists `@tac` as a registry with a `file:` URL so `shadcn add @tac/button` resolves against this directory during development:

```jsonc
// packages/ui/components.json
{
  "registries": {
    "@tac": "file:./registry/{name}.json"
  }
}
```

## Production hosting (Sprint 4 / S4.2 — pending)

Pick one of:

| Host | Pros | Cons |
|---|---|---|
| **GitHub Pages** from a `tac-registry` branch | Free, version-controlled, auth via token | Public repo, or org-private repo with token gate |
| **S3 + CloudFront** | Standard pattern, full control | Infra to manage |
| **Vercel** static deployment of this dir | Easy, fast CDN | Cost if private |

Once a host is chosen, update `packages/ui/components.json`:

```jsonc
{
  "registries": {
    "@tac": "https://your-host/r/{name}.json"
  }
}
```

The hosted directory must contain both `registry.json` and every `<name>.json` listed in it.

## Maintenance workflow

```bash
# 1. Add a new item to the index
$EDITOR packages/ui/registry/registry.json
# Add an entry to `items[]` with: name, type, title, description,
# dependencies (npm), registryDependencies (Radix etc.), and files[]
# pointing at the relative path under packages/ui/.

# 2. Rebuild the per-item JSON files
pnpm --filter @workspace/ui registry:build

# 3. Verify the build is in sync (CI gate)
pnpm --filter @workspace/ui registry:check
# Exits non-zero if any <name>.json is stale relative to its source file.

# 4. Commit both the index AND the generated files
git add packages/ui/registry/
git commit -m "registry(@tac): add <name>"
```

The `registry:check` script is wired into CI so a source-file change without a registry rebuild fails the build.
